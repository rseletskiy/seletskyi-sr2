## Компіляція і запуск основних прикладів

Потрібен компілятор із підтримкою C++17. Команди виконуються в корені репозиторію, де лежать main.cpp і student.hpp. main.cpp та tests.cpp мають окремі функції main, тому їх слід компілювати окремо.

Windows PowerShell:

```powershell
g++ -std=c++17 -Wall -Wextra -Wpedantic main.cpp -o sr2.exe
.\sr2.exe
g++ -std=c++17 -Wall -Wextra -Wpedantic tests.cpp -o tests.exe
.\tests.exe
```

Linux або macOS:

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic main.cpp -o sr2
./sr2
g++ -std=c++17 -Wall -Wextra -Wpedantic tests.cpp -o tests
./tests
```

Результат перевірок:

```text
All tests passed
```

## 1 Клас Student та приватні поля

У student.hpp клас Student має поля name, group і course. Конструктор за замовчуванням задає Unknown, Not assigned і курс 1. Конструктор із параметрами приймає ім’я, групу та курс. Методи setGroup і setCourse змінюють дані, output виводить стан об’єкта.

У main.cpp створено два об’єкти: first через конструктор за замовчуванням і second через конструктор із параметрами. Після цього second отримує нову групу та курс.

Поля name, group і course мають бути private. Зовнішній код не повинен змінювати їх в обхід інтерфейсу класу. Наприклад, прямий запис course = 0 порушив би правило додатного номера курсу. Метод setCourse перевіряє значення і викидає std::invalid_argument до зміни поля. Конструктор із параметрами використовує ту саму перевірку.

Приватність name і group також відокремлює внутрішнє подання даних від коду, який користується класом. Конструктори, setGroup, setCourse та output є public, бо це доступні зовні операції. Поточна навчальна модель перевіряє номер курсу; перевірку формату імені та групи в ній не задано.

## 2 Навчальна модель Tovar

Клас Tovar в examples.hpp містить приватні поля:

- name: назва товару;
- price: ціна одиниці в гривнях;
- quantity: кількість одиниць.

Методи getName, getPrice і getQuantity надають доступ для читання. setPrice змінює ціну, sell списує продану кількість, totalValue обчислює вартість залишку, output виводить дані.

У main.cpp створено book із ціною 125.50 та кількістю 3 і pen із ціною 20.00 та кількістю 10. Після продажу двох книжок у book залишається одна одиниця вартістю 125.50.

Конструктор відхиляє від’ємний залишок. Ціна має бути скінченним невід’ємним числом. sell відхиляє нульову, від’ємну та більшу за залишок кількість; після відмови стан не змінюється. Для ціни в цьому навчальному прикладі використано double.

## 3 Порівняння принципів ООП

| Принцип | Зміст | Приклад у роботі |
|---|---|---|
| Абстрагування | Вибір властивостей і дій, потрібних для конкретної задачі | Tovar описує назву, ціну, залишок і продаж; не моделює всі фізичні властивості товару |
| Інкапсуляція | Об’єднання стану з операціями та обмеження прямого доступу до нього | Приватні поля Student і перевірка значення в setCourse |
| Успадкування | Побудова похідного класу на основі базового з відношенням «є різновидом» | Car і Bicycle публічно успадковують Vehicle |
| Поліморфізм | Виклик спільного інтерфейсу з поведінкою, що залежить від фактичного типу об’єкта | description через std::unique_ptr<Vehicle> викликає реалізацію Car або Bicycle |

Абстрагування визначає, що потрібно описати в моделі. Інкапсуляція визначає, як користуватися об’єктом і захищати його стан. Успадкування задає зв’язок між типами, а динамічний поліморфізм дозволяє працювати з різними похідними типами через базовий інтерфейс.

## 4 Клас Prylad

Prylad в examples.hpp зберігає назву name і потужність powerWatts. Метод output виводить опис приладу. Метод energyKwh обчислює спожиту енергію за формулою:

```text
енергія, кВт·год = потужність, Вт / 1000 × час, год
```

У main.cpp лампа потужністю 60 Вт працює 5 годин. Результат становить 0.30 кВт·год. Від’ємні та нескінченні значення потужності чи часу, а також NaN, відхиляються.

## 5 Конструктори класу Payment

Payment має два приватні поля: amountKopiyky та currency.

Конструктор Payment() створює об’єкт із нульовою сумою і валютою UAH. Конструктор Payment(15499, "UAH") задає суму 15499 копійок, тобто 154.99 гривні. Використання цілих найменших одиниць дозволяє зберегти цю суму без дробового представлення.

Обидва конструктори продемонстровано в main.cpp. Конструктор із параметрами відхиляє від’ємну суму та порожню валюту. Створення об’єкта описує дані платежу й не виконує переказ коштів.

## 6 Ієрархія транспортних засобів

Базовий абстрактний клас Vehicle має приватне поле brand, захищений конструктор та захищений метод getBrand. Похідні класи отримують марку через цей метод, а не через прямий доступ до поля.

Car і Bicycle успадковують Vehicle через public. Автомобіль і велосипед є різновидами транспортного засобу, тому таке успадкування відповідає предметній області.

Vehicle оголошує чисто віртуальну description. Кожен похідний клас надає власну реалізацію з override. У main.cpp створено Car("Ford") і Bicycle("Trek") та виведено їхні описи. Об’єкт Vehicle безпосередньо створити не можна, бо клас абстрактний.

## 7 Неоднозначність множинного успадкування

Scanner та Printer мають методи з однаковою назвою status. MultiFunctionDevice успадковує обидва класи. Для виразу device.status() компілятор не може вибрати, який базовий метод викликати.

У main.cpp цей вираз міститься всередині умовного блоку SHOW_AMBIGUITY. У звичайній збірці блок вимкнений. Щоб відтворити помилку, потрібно виконати:

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic -DSHOW_AMBIGUITY main.cpp -o ambiguity-demo
```

Компіляція цього варіанта має завершитися відмовою. Перевірений діагностичний фрагмент GCC:

```text
error: request for member ‘status’ is ambiguous
```

У роботі показано два способи розв’язання:

1. Уточнити базовий клас: device.Scanner::status() або device.Printer::status().
2. Визначити власний однозначний метод OfficeDevice::status(), який викликає обидві базові реалізації та об’єднує результати.

У цьому прикладі базові status не є віртуальними; метод OfficeDevice надає власний інтерфейс і приховує однойменні базові методи. Звичайна збірка працює без неоднозначного виклику.

## 8 Віртуальна функція та поліморфний виклик

У main.cpp створено std::vector<std::unique_ptr<Vehicle>>. У ньому зберігаються Car("Toyota") і Bicycle("Giant").

Цикл викликає vehicle->description() через вказівник базового типу. Завдяки virtual компілятор забезпечує вибір реалізації за фактичним типом об’єкта: для автомобіля виконується Car::description, для велосипеда Bicycle::description.

Результат:

```text
Car: Toyota
Bicycle: Giant
```

Деструктор Vehicle також віртуальний. Тому видалення похідного об’єкта через std::unique_ptr<Vehicle> коректне.

## 9 Запит до ШІ та ручна перевірка

Приклад запиту:

> Перевір C++17-клас Student із файлу student.hpp та приклади його використання в main.cpp. Знайди помилки ініціалізації, доступу до полів і перевірки номера курсу. Окремо перевір поведінку конструктора за замовчуванням, конструктора з параметрами та setCourse для 0 і від’ємних значень. Для кожного зауваження наведи конкретний фрагмент коду, поясни наслідок і запропонуй мінімальне виправлення. Відокрем помилки від побажань щодо стилю. Не додавай вимог до формату імені чи групи, яких немає в умові. Не стверджуй, що компіляцію або тести виконано, якщо ти їх не запускав.

Після відповіді потрібно перевірити:

| Тип відповіді | Ручна перевірка |
|---|---|
| Твердження про помилку компіляції | Зібрати програму з C++17 та попередженнями; звірити діагностику з конкретним рядком |
| Пропозиція змінити private на public | Перевірити, чи не з’явився прямий запис некоректного курсу в обхід setCourse |
| Зміни конструктора | Порівняти результати створення об’єктів за замовчуванням і з параметрами |
| Зміни перевірок | Викликати setCourse із 0 і -1; перевірити виняток та незмінність попереднього стану |
| Нові правила для імені або групи | Зіставити їх з умовою; не додавати довільних обмежень |
| Твердження про «успішні тести» | Самостійно запустити tests.cpp і перевірити результат та код завершення |

tests.cpp перевіряє обидва конструктори Student, зміну групи й курсу, відмову за некоректного курсу та збереження попереднього стану. Рекомендації ШІ потребують перевірки компілятором, тестами й умовою завдання.

## 10 Мінімальний C++-проєкт у VS Code

Папка vscode-minimal містить один файл C++ main.cpp і налаштування .vscode/tasks.json. У конфігурації є завдання Build C++ та Run C++. Завдання Run C++ спочатку компілює файл, потім запускає програму в терміналі VS Code.

Локальний запуск у редакторі:

1. Перевірити в терміналі команду g++ --version. Компілятор має бути встановлений і доступний через PATH.
2. Відкрити у VS Code саме папку vscode-minimal через File > Open Folder.
3. Відкрити Terminal > New Terminal.
4. Виконати команди для своєї системи або обрати Terminal > Run Task > Run C++.
5. Перевірити вивід C++ project works.

Windows PowerShell, з папки vscode-minimal:

```powershell
g++ -std=c++17 -Wall -Wextra -Wpedantic main.cpp -o student_demo.exe
.\student_demo.exe
```

Linux або macOS, з папки vscode-minimal:

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic main.cpp -o student_demo
./student_demo
```

Результат:

```text
C++ project works
```

Для налаштувань папку vscode-minimal потрібно відкрити як корінь робочої області: змінна ${workspaceFolder} в tasks.json має вказувати на неї. Опис формату завдань: https://code.visualstudio.com/docs/debugtest/tasks.

## Перевірка коду

Основну програму, tests.cpp та окремий мінімальний main.cpp перевірено компілятором GCC 14.2 у Linux з прапорцями -std=c++17 -Wall -Wextra -Wpedantic -Werror. Вони компілюються без попереджень, обидві програми запускаються, tests.cpp виводить All tests passed. Варіант із SHOW_AMBIGUITY дає очікувану помилку неоднозначності. Конфігурація tasks.json містить окремі параметри назв виконуваних файлів для Windows; її запуск у VS Code потрібно виконати локально.
